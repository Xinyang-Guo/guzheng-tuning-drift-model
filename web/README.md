# 听弦 · 双模型古筝跑音预测网页

首次运行 Python 版本需要先安装 `requirements.txt`，将授权原始工作簿放入 `data/古筝调音数据.xlsx`，然后运行 `python src/guzheng_future_validation.py` 生成所需的时间验证指标。公开文件包不含原始工作簿；无需原始数据的演示请使用 `docs/` 静态网页。

准备好以上文件后，在项目根目录运行：

```bash
conda activate myenv
python web/server.py
```

打开 http://127.0.0.1:8765 。终端按 Ctrl+C 停止。可用 `--port 8766` 指定另一端口。

默认首页为青衫花簪琴师新版：山水琴亭、木框手记和二十一弦卡片。“朝露 / 暮色”只切换外观，不修改预测；动画遵循系统的减少动态效果设置。

## 模型选择

| 模型 | 网页配置 | 历史时间留出 MAE | 历史时间留出 R² |
|---|---|---:|---:|
| 随机森林（默认） | 300 棵树、深度 4、叶节点至少 20、max_features=0.6、min_samples_split=2、random_state=42 | 10.04 | 0.0273 |
| 岭回归 | StandardScaler + Ridge，alpha=316.22776601683796 | 6.53 | 0.5960 |

两者均使用湿度、湿度变化、温度、温度变化、弦编号这五个变量，古筝编号不参与预测。服务启动时在全部历史记录上分别拟合，模型与元数据保存在 `output/web_random_forest/` 和 `output/web_ridge/`。岭回归的标准化与预测保存在同一个 Pipeline 内。

指标来自此前时间留出实验，并非全历史重训模型的未来成绩。此前时间验证中岭回归表现更好；真实天气预报输入误差仍未评估。

首次选择模型后点击“预测 21 根弦”。已有结果时，选择另一模型会自动使用当前环境重算。切换过程中清空旧数值并禁止下载，迟到的旧请求不能覆盖新模型结果；环境输入改变后也会提示结果需更新。

## 输入与输出

- 湿度填百分比（%），湿度变化填百分点，服务自动除以 100。例如 60% → 70% 的变化填 `10`。
- 温度与变化量单位均为 ℃，降低填负数；前一时点的温湿度也须在合理范围内。
- 弦编号 1～21 自动填入；预测图、摘要和 CSV 均显示本次模型。CSV 文件名包含中文模型名称，各行包含模型标识。
- 环境来源只标注预报/估计或确定值，不改变模型。天气数据需手动输入，优先估计古筝所在室内环境。
- 偏差沿用原 Excel 单位，正负方向定义尚未确认；不直接表示偏高/偏低或调弦操作量。
- 所有页面资源与推理均在本地，不依赖外部字体、CDN 或天气服务。

## 页面地址

- `/`、`/index.html`、`/qinshi.html`：新版琴师和双模型功能，源文件 `web/qinshi.html`。
- `/original.html`：保留的旧版页面，源文件 `web/index.html` 未修改；旧页面继续默认使用随机森林。新版“关于模型与预测结果”中有旧版链接。

## API 与验证

- `GET /api/models`：返回可用模型、默认模型、参数、训练范围和历史评估。
- `POST /api/predict`：接收环境条件、`mode`、`model`；模型为 `random_forest` 或 `ridge`。省略模型时默认随机森林以兼容旧版；无效模型返回 400。
- 响应包含 `model`、`model_name`、`model_params`，用于结果追溯。
- `GET /api/model`：保留原随机森林元数据接口。

服务开启后测试：

```bash
python web/test_app.py
python web/test_browser.py --url http://127.0.0.1:8765 --variant
```

浏览器测试需要 Playwright 与 Chromium。测试覆盖两模型与真实已保存模型数值一致、岭回归标准化、输入校验、快速切换、模型标注导出，以及桌面和手机布局。
